00 — The setup

Three kinds of prompt

The model trains on three prompt types at once. A suffix tells them apart.

budget
"Think for N tokens." Answer within N tokens. 60% of rows.
free
No limit. Think as long as needed. 20% of rows.
nothink
No thinking at all. 20% of rows.

The reward takes the task score and subtracts a penalty for missing the budget:

reward = task_score − α · |budget − n_total|

Writing too little is punished as hard as writing too much. That is on purpose. Stage A teaches the model what a token count means. Stage B, which only punishes going over, is meant to run afterwards starting from a Stage A checkpoint.

Each of the three data sources gets its own α, so the length penalty stays in proportion to how much that source's task score varies. GRPO, 16 samples per prompt, no KL, advantage is reward minus the group mean.

01 — What we changed

Seven fixes went into Run A

They all came from the run before, on 2026-08-19, which broke on math. Budgeted rollouts started writing an empty <think></think> and moved the reasoning into the answer instead (think 8045 → 3 tokens, answer 399 → 1376). Only the think span was penalised, so moving the work was cheaper than shortening it.

Each fix below has its verdict from Run A's 101 steps.

C1

Count the whole response, not just the thinking

The budget now applies to think + answer. Whatever you penalise is the only thing that gets shorter, so leaving the answer free made moving the work the cheapest way to comply.

answer length over 101 steps: 433 → 298 tokens. It never grew.
The move-the-work trick never came back.
Worked
C2

Require a minimum amount of thinking

A budgeted answer that thinks for fewer than max(32, 0.10 × budget) tokens scores as no attempt. Without this, the empty think block is a trap the model cannot climb out of: once all 16 samples in a group write it, the length term has no spread inside the group, so it drops out of the advantage completely.

floor failures 5.5% → 0.8% · empty think blocks 2.9% → 0.2%
groups with no reward spread at all: 0.0% for the whole run. The signal stayed alive.
Worked
C3

Math α from 3e-4 down to 5e-5

At 3e-4 the length penalty varied 2.24× more than the task score inside a group, so length mattered twice as much as being right. The cut was meant to bring math in line with the other two sources.

it stopped the collapse, but left length at 0.24 of the task spread against a target of 0.60.
math still wrote 5649 tokens against a ~3000 budget — 1.9× over.
Too far
C4

Actually log the per-source metrics

compute_data_metrics runs in the TaskRunner actor, but the patch was only imported by the reward workers. No per-source or LCPO curve had ever reached wandb. That is why the previous collapse went unseen from step 20 to step 170.

every critic/per_source/* and critic/lcpo/* series is present for all of Run A.
One catch: output.log cuts each step line at 4096 characters, so they look missing in the console. They are in the run history.
Worked
C5

Label the validation ladder by variant

verl groups validation by the data_source string. All eight ladder variants were being averaged into one number per eval set, so the score-versus-budget curve could not be drawn at all. Now tagged @b00256 / @free / @nothink.

six budget rungs × three eval sets now come out separately.
Every ladder chart in this report depends on this fix.
Worked
C6

Stop using a Ray setup hook

The hook runs in every worker before Ray hands out GPUs. It imported verl, which calls torch.cuda.is_available() on import. That locked every process to all 8 GPUs and made CUDA ignore the per-actor CUDA_VISIBLE_DEVICES set later. Replaced with a custom full_mix.main_ppo entry point.

Run A finished 101 steps on 8 GPUs with no device errors. MFU steady at 0.375.
Worked
C7

Flip the test that had blessed the bug

A test had pinned the move-the-work gap as expected behaviour — "the reminder to add a penalty if that metric starts moving". It moved. The test was inverted, and new tests cover the think floor and free/nothink staying ungated.

14/14 passing in full_mix/lcpo/test_lcpo.py.
Replaying the real broken rollout through the old settings reproduces the −0.994 mean from the step-170 dump, which proves the old behaviour is modelled right.
Worked
Verdict on the fixes

Six of seven did their job. Every way the 2026-08-19 run broke stayed fixed for 101 steps. The one that missed, C3, was too gentle rather than too harsh. Section 06 is about trying to correct that.

02 — Did the fixes work

Nothing broke the way it broke last time

C1 and C2 had one job: stop the model writing an empty think block and calling it done. They did it, and they held for the whole run.

The floor also kept the learning signal alive. If every sample in a group writes the same empty block, the length term has no spread and stops teaching anything. That never happened: zero groups hit zero reward spread at any step.

03 — Task quality

Shorter and better at once

Average answer length fell from 3654 to 2777 tokens, a 24% cut. Accuracy did not pay for it. Two of the three validation sets improved and the third held flat.

The gsm8k grading bug

gsm8k asks for the answer after ####. When thinking, the model increasingly writes 109#### instead of #### 109. Right answer, wrong side of the marker. The grader gives it zero. Answers ending in a bare #### went from 18.1% at step 0 to 47.6% at step 100.

Corrected, gsm8k free mode is 0.90 at step 100, not 0.52. Budgeted rows are 0.81, not 0.30. Training math uses \boxed{}, so this never touched the reward — it only broke the measurement. But it broke it for the entire run.

04 — Budget following

It hits the budget when the budget is what it wanted to write

Over training it is the same. The correlation between the budget asked for and the length written was 0.024 in the first ten steps and 0.049 in the last ten. Perfect control would be 1.0.

05 — Why it failed

It found the answer that ignores the number

With a symmetric penalty, the best strategy that never reads the budget is to write the median budget every time. That is exactly where it landed.

median budget across the run 3046 tokens model's median answer, late run 2632 tokens

Average signed error improved a lot, from +1412 tokens to +289. Average relative error barely moved, 1.95 → 1.14. In other words the whole distribution shifted onto the target without getting any sharper.

The second problem is that the length signal was weak and getting weaker. Advantage is reward minus the group mean, so what teaches the model is how much each term varies inside a group. As the model's lengths converged, the length penalty varied less, so it taught less.

One thing that is not the problem

It looks like giving all 16 samples in a group the same budget should starve the signal — no contrast inside the group, so nothing to learn the mapping from. The rollouts say otherwise. In groups sitting above their budget, longer answers correlate with lower reward at −0.988. In groups sitting below, +0.974. Small budgets push shorter, big budgets push longer, exactly as designed. The gradient points the right way everywhere. It is just too small, and at the extreme rungs the model never writes anything close to the target, so it never gets useful evidence.

06 — Raising α

Why we made the penalty stronger

Three things from Run A pointed the same way.

  • The penalty was running at about half strength. The target was 60% of each source's task spread. Measured over steps 70–89: ifeval 0.33, chat 0.33, math 0.24.
  • It was fading. The spread of |budget − n_total| inside a group fell from 1225 to 711 tokens, so whatever you set drifts down about 40% over a run.
  • Making answers shorter looked free. Inside a group, the shorter samples scored better: −0.02 to −0.09 on ifeval, −0.12 to −0.20 on chat and math. Long answers are where the model rambles. So there seemed to be no accuracy at risk.

We set the penalty to 0.8 of each source's task spread instead of 0.6, expecting it to fade toward 0.6 by the end of a run.

We also looked at changing the shape of the penalty and decided against it. Dividing by the budget, α·|b−n|/b, sounds fair but is not. The spread of |b−n| is about the same at every rung, so one α would hit the ≤384 rung 14.7× harder than the >5000 rung. The plain absolute form is already even, at 1.7× across rungs, and |log(n/b)| is 1.6×. We left the shape alone.

What this calibration missed

It checked how strong the penalty is next to task-score noise. It never checked whether, at that strength, quitting scores better than trying. For ifeval and chat those are the same question. For math they are not.

07 — Run B

Math emptied the think block

Run B is the new α values and nothing else. For twenty steps it looked like an improvement. Then math fell off a cliff.

08 — The arithmetic

Quitting started paying better than trying

The think floor zeroes the task score. It does not add a penalty. So a collapsed row still carries only its length term — and for math, collapsing improves that term. Math's honest answer is far longer than the budget. A collapsed one is much closer to it.

Here is the condition, and it is the check the calibration should have included:

α < task_score_honest ⁄ ( |b − n_honest| − |b − n_collapsed| )

Only math is exposed, and it is the same default-length effect from section 04. Math writes about 9000 tokens against a ~3000 budget, so quitting moves it closer to target: error 6589 → 3093. It saves penalty and looks more obedient. Chat and ifeval write ~2000 against ~3000, so quitting would make their error worse (1892 → 3595). It never pays for them at any α — their break-even is a thousand times higher than anything you would set.

The old math α of 5.0e-5 sat safely under the 9.8e-5 line. The new 1.6e-4 sits 1.6× above it. That one crossing is the whole of Run B.

09 — What to do

Four things

  • Stop Run B. It is past step 45 and every step makes the collapse worse.
  • Math α to 7e-5. Under the 9.8e-5 break-even with room to spare, still 1.4× the old value. Leave chat at 3.7e-4 and ifeval at 2.4e-4 — both are working.
  • Make quitting cost more than the length it saves. Right now compute_reward sets the task score to zero and leaves the length term standing, so a quit row can out-earn an honest one. Give a floor failure a fixed worst-case reward instead. That closes it at any α, rather than relying on α staying under a moving line.
  • Fix the gsm8k #### grading. It has been reporting about half the real accuracy since step 0.

One thing to plan for rather than patch later: math's break-even α rises as the model gets shorter, because the gap between an honest answer and a quit one narrows. A single fixed α is either too weak at the start or unsafe at the end. It should be a schedule.

And the harder limit has not moved. A budget far below what a source needs is not reachable at any α. The model either ignores it, as in Run A, or quits on it, as in Run B. About a quarter of math's budgeted rows ask for under 1500 tokens against a normal length of 5772.
