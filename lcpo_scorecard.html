00 — How to read this

Two numbers per box

Every slice is judged on two things, and they can move in opposite directions.

on target
Share of answers landing within ±25% of the budget asked for. Higher is better.
accuracy
Raw task score, before any format or floor penalty. Higher is better.
ratio
Tokens written ÷ tokens asked for. 1.00× is perfect. Above 1 is too long, below 1 is too short.
corr
How well length tracks the budget across the six rungs. 1.00 means bigger budgets always get longer answers. 0 means the budget is ignored.

Training budgets come from a continuous range, so they are grouped into five rungs. Eval budgets are fixed at six exact values.

One warning about gsm8k. Its grader wants the answer after #### and the model often writes it before. That marks correct answers wrong. Every gsm8k number here is corrected for it. Your dashboard is not.

10 — Watch list

What to act on

1. The model overshoots big budgets, and that is where accuracy dies

This is now the only real problem left. The model learned to treat a big budget as an order to write a lot — and it writes more than it was even asked for.

All three overshoot. Only gsm8k is badly hurt by it, because a gsm8k question needs about 700 tokens and it is now writing ten times that. MATH-500 and IFEval can absorb the extra text.

Stage B fixes this exactly. Stage B only punishes going over, so a big budget stops being an order to pad and becomes a ceiling. Stage A has now done its job — it taught the number-to-length mapping, which is what it exists for. This is the strongest argument yet for moving on.

2. Compressing hard problems costs accuracy, and no reward change fixes that

MATH-500's 256 rung fell 0.79 → 0.66 and its 512 rung 0.81 → 0.71 as the model started genuinely compressing rather than ignoring the request. That is not a reward bug. A hard maths problem in 256 tokens is simply harder.

Worth knowing so you do not chase it. The rest of MATH-500 held: the 4000 and 6000 rungs went up, and free mode is at its best of the run at 0.84.

3. The gsm8k grader is still broken

The model writes 109#### instead of #### 109 and the grader scores it zero. Every gsm8k figure in this report is corrected for it. Your dashboard is not, so it under-reports gsm8k badly. Worth fixing before the next run so the ladder is readable live.

4. Entropy is still climbing

Policy entropy went 1.38 → 1.75 over the run and has not settled. Everything else is stable (clip fraction 0.0005, gradient norm 0.066), so this is not an emergency, but a policy that keeps getting less certain is worth an eye if you extend the run.

What is going well

  • Budget following is solved: on target 15.2% → 65.8%, correlation 0.025 → 0.893, median ratio 0.98×.
  • Overall accuracy went up while that happened: 0.435 → 0.518.
  • IFEval gained both at once — accuracy 0.519 → 0.668, on target 18.1% → 66.5%.
  • Chat did too: accuracy 0.408 → 0.470, correlation 0.913.
  • Free-mode accuracy is at its best of the run on all three eval sets.
  • The math collapse has not returned in 290 steps. At step 360: 0.00% empty think blocks, 0.00% floor failures, 99.4% well-formed.
  • Mean reward +0.002 → +0.432.

The run is still inside its first epoch and both numbers are still moving. Nothing here argues for stopping — but Stage A has taught what it can teach, so Stage B is the natural next step.
