00 — The arc

Four runs

The task: teach one model three behaviours at once — think within a token budget, think freely, or not think at all — told apart only by a line in the prompt.

R1

19 Aug — the relocation exploit

Only the think span was penalised. Budgeted math learned to emit an empty <think></think> and move the reasoning into the answer, where nothing counted it.

think 8045 → 3 tokens while the answer grew 399 → 1376.
Lesson: whatever you penalise is the only thing that gets compressed.
Failed
R2

23 Aug — seven fixes, but the budget still ignored

Penalise total length, floor the think span, fix the metrics, tag the val ladder. All held. But the length penalty was set too weakly.

every structural failure closed and stayed closed for 101 steps.
Budget-to-length correlation after 101 steps: 0.05. The model learned one length and ignored the number.
Too weak
R3

24–26 Aug — stronger penalty, and it worked

Alphas roughly tripled. Math collapsed for 60 steps, recovered on its own, then the budget mapping appeared and kept improving for 480 steps.

on target 15% → 78%, correlation 0.03 → 0.93, ratio 0.99×.
Accuracy rose at the same time: ifeval 0.52 → 0.68, chat 0.41 → 0.54.
The goal
R4

26–27 Aug — Stage B, the ceiling

Switch to a reward that only punishes overshoot, and reword the prompt to "a maximum of N tokens". Meant to let bigger budgets buy better answers.

length fell to 0.41× of budget, on target to 4.9%.

Eight hundred steps in one picture

02 — What worked

The two changes that mattered

Of everything tried, two changes account for almost all the progress.

1. Penalise the whole response, not just the thinking

This closed the relocation exploit permanently. Once total length was the target, moving reasoning into the answer stopped helping, and the empty think block never came back in 800 further steps.

2. Make the length penalty strong enough to matter

At the original strength the length term's within-group spread was 0.24–0.33 of the task score's. The model responded by learning a single length near the median budget — the best strategy that ignores the number entirely. Roughly tripling the penalty is what made the mapping appear, and it took 180 steps before anything visible happened.

Everything else — the think floor, the metric plumbing, the val ladder tagging, the entry-point fix — was necessary but not sufficient. They stopped failures rather than causing progress.

03 — Why Stage B slipped

A one-sided reward cannot hold length up

Stage B's length term only subtracts for writing too much. It never adds for writing more:

mult = clip(α·(budget − n) + δ, 0, 1) → 1.0 for anything under budget

About 88% of rows now sit at exactly 1.0, so for most of the batch the length term contributes no gradient at all. The only thing that stops the model shrinking is the answer becoming wrong — and that is a soft, late floor.

It is not a smooth slide. Length fell to 0.42×, recovered to 0.59× around step 140, held near 0.53× for a hundred steps, then fell again to 0.41×. The model and the penalty chase each other: shrinking switches the penalty off, accuracy eventually pulls back, the penalty re-engages, and it repeats.

Two thirds of the initial drop was not training at all. The first evaluation uses the same weights as Stage A's final checkpoint and only changes the prompt from "Think for N tokens" to "Think for a maximum of N tokens". That alone cut on-target from 46.5% to 22.9%. The wording is part of the specification, and changing it discarded the calibration.

And it did not buy what it was for

Stage B exists so that a bigger budget buys a better answer. Measured as accuracy gained per 10× more budget: MATH-500 +0.085 → +0.077, gsm8k +0.044 → +0.025, IFEval +0.005 → +0.046. Two down, one up, from a base that was already there. No net gain.

That was foreseeable from the data: only math has a real compute-accuracy slope, and it is a quarter of the mix. There was little monotonicity available to buy.

Ship Stage A step 480. It is the model the project set out to build: ask for 2,000 tokens and you get about 2,000, at every budget from 256 to 6,000, with accuracy above where it started on all three sets.

Stage B's checkpoint is a real alternative if you never need the number to be literal — it answers better per token and its dial is still ordered — but "N means roughly 0.4N, and drifting" is a hard property to document, and the correlation is now falling as well as the scale.

If you want the ceiling wording too

Keep Stage A's symmetric reward and change only the prompt, then retrain briefly so the calibration transfers to the new phrasing. That gets the "maximum of N" semantics without giving up the scale. It is a short run, not a new stage.

05 — What we learned

Seven things worth keeping

  • Whatever you penalise is the only thing that gets compressed. Penalise the think span and the reasoning moves into the answer. This cost one entire run.
  • A weak symmetric penalty teaches the median, not the mapping. The model wrote one length close to the median budget — the optimal strategy for ignoring the number — and looked like it was "slowly learning" for 180 steps.
  • Check whether giving up beats trying, not just whether the signal is strong. Raising the penalty crossed a threshold where a zero-scoring short answer out-earned an honest attempt, and math collapsed. The condition is α < task ⁄ (|b−nhonest| − |b−nquit|).
  • That collapse was self-limiting. As the model shortened, the honest penalty fell and honest work paid again. It climbed out unaided by step 80. Stopping the run — which I recommended — would have thrown that away.
  • A one-sided reward cannot hold a quantity up. Stage B can only punish overshoot, so nothing resists shrinking except the task score.
  • The prompt wording is part of the reward specification. Changing four words cost half the length calibration before a single gradient step.
  • Measure the grader before believing the metrics. The gsm8k scorer wanted the answer after #### with exactly one space, and rejected 48% of correct answers. It made gsm8k look like it was collapsing for two reports running.
